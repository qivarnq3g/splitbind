# Frontend Design and Motion Invariants

## Current implementation notice - 2026-09-09

The presentation guidance below is historical and superseded by [Frontend refinement QA](frontend-refinement-qa.md) and the app worktree's `design.md`. The current Evidence desk removes chambers, CryptographicMotif, laser scans, seals, fake telemetry, mobile drawers and root overflow clipping. It uses visible mobile tabs, verdict-first results and technical disclosure. GSAP is limited to scoped 180ms opacity and 220ms real status changes, disabled for reduced motion. Upload stages are not cryptographic-processing evidence. Do not restore previous false-positive signature or blanket tampering copy. The inspected Vite configuration targets the local backend, not the historical production proxy described below.

## Historical implementation notes (not current requirements)

Verified architectural and implementation facts for SplitBind frontend redesign:

- Design Token Declaration Invariant: `src/test/design-system.test.tsx` parses `tokens.css` and `app.css` using regular expressions `var(--[a-z0-9-]+)` and strictly verifies that every referenced CSS variable is explicitly declared in `:root`. Referencing undeclared CSS variables fails CI immediately.
- OpenAPI Job Status Contract: In `apps/web/src/api/generated/schema.d.ts`, the asynchronous job status enum defines `"created" | "queued" | "processing" | "succeeded" | "failed" | "retryable_failed" | "dead_lettered" | "cancelled"`. The active executing state is strictly `"processing"` (not `"running"`). Comparing with `"running"` triggers TypeScript error `TS2367`.
- Viewport and Responsive Fidelity: The original desktop-only restriction (`min-width: 64rem; overflow-x: auto;`) was replaced by fluid container width (`width: 100%; overflow-x: hidden;`) and responsive layouts (`@media (max-width: 48rem)` and `@media (min-width: 48.0625rem) and (max-width: 64rem)`). Mobile layouts recompose the two-column workbench into stacked cards and provide a slide-down/drawer navigation menu.
- GSAP Context and Reduced-Motion Guardrail: In `MotionRoute.tsx`, GSAP entrance timelines register plugins via `gsap.registerPlugin(useGSAP)` and scope transitions to `root.current` with `revertOnUpdate: true`. When `prefers-reduced-motion: reduce` is active, motion transforms are entirely bypassed, using an instant 0.08s opacity fade. Any transform applied during motion must clear props (`clearProps: "transform,opacity,visibility"`) upon completion to prevent fixed/sticky header clipping.
- Compact Control Hit Targets: Accessibility tests assert that `.copy-identifier` and `.technical-details summary` maintain minimum dimensions matching `var(--control-height)` (44px / 2.75rem) to ensure reliable touch and keyboard interaction.
- Empty State Architecture: Empty states across unselected files, empty jobs, and missing evidence must use semantic regions (`role="region"`) and descriptive labels without generic placeholder text or layout shift.
- JSDOM Headless ScrollTrigger Guard: In JSDOM test suites, `window.matchMedia` is undefined at import time. Calling `gsap.registerPlugin(ScrollTrigger)` at module level throws `TypeError: _win.matchMedia is not a function`. Registration must be guarded with `if (typeof window !== "undefined" && typeof window.matchMedia === "function") { gsap.registerPlugin(ScrollTrigger); }` while `useGSAP` remains safe to register unconditionally.
- Header Stack Layout Invariant: In `.page-heading`, adding badges above titles breaks two-column CSS grids (`grid-template-columns: minmax(0, 1.15fr) minmax(18rem, 0.85fr)`), pushing `h1` to column 2 and causing extreme word-by-word vertical wrapping on mobile viewports. `.page-heading` must strictly use a unified vertical flex stack (`display: flex; flex-direction: column; align-items: flex-start;`).
- Laser Scan and Cryptographic Lattice Visual Feedback: During document verification upload, a vertical laser beam (`.scan-laser-beam`) sweeps the dropzone, providing real-time visual affirmation of algorithmic inspection. In the login view, an SVG cryptographic lattice with concentric rings and DWT coordinate axes provides authentic security branding without violating the strict 2-paragraph DOM contract.
- Cryptographic Motion Motif Architecture: The reusable `<CryptographicMotif stage="..." />` primitive in `apps/web/src/components/CryptographicMotif.tsx` maps the cryptographic pipeline (Document -> Hash -> DWT/DCT frequency decomposition -> Ed25519 signature -> Verification -> Evidence -> Seal) to semantic SVG layers (wavelets `.motif-wavelet-path`, coordinate axes `.motif-axes`, hash fragment pips `.motif-hash-pip`, converging nodes `.motif-node`, and seal geometry `.motif-seal-geometry`). GSAP timelines are scoped via `useGSAP` with `revertOnUpdate: true`. When `prefers-reduced-motion: reduce` is active or in headless test environments without `matchMedia`, looping transforms are bypassed and props are cleared (`clearProps: "all"`) to preserve clean static presentation.
- Motion Token Invariant: Duration tokens (`--dur-pulse`, `--dur-scan`, `--dur-decompose`), easing tokens (`--ease-subtle`, `--ease-spring`), and geometry tokens (`--motif-node-size`) must be defined in `tokens.css` under `:root` to satisfy the strict regex token validation in `src/test/design-system.test.tsx`.
- GSAP Nested Repeat Timeline Invariant: In GSAP, nesting a child tween with `repeat: -1` inside a parent timeline (`gsap.timeline({ repeat: -1 })`) renders the parent timeline's duration infinite (`Infinity`). Consequently, the parent timeline never completes or repeats, causing sibling tweens with finite durations (such as staggered pips) to execute once and freeze while the infinite child tween runs indefinitely. Indeterminate looping telemetry across multiple elements must either set `repeat: -1` directly on the sibling tweens/staggers or orchestrate them as concurrent independent tweens.
- Issuance Signing Chamber & DOM Collision Invariant: In `IssueDocumentPage.tsx`, the `.issuance-chamber` acts as a non-blocking cryptographic telemetry companion alongside the form, orchestrating 5 stages (intake -> hashing -> decomposing -> signing -> sealed) with `<CryptographicMotif stage={stage} />`. To prevent test breakages in `design-system.test.tsx` (which checks `screen.getByText("Chưa chọn tệp")` with strict cardinality 1), telemetry placeholder text must avoid colliding with primary input labels (e.g. using "Chờ tệp PDF" rather than duplicate "Chưa chọn tệp") and avoid matching the banned regex `/API|endpoint|worker|UUID/i`. Furthermore, queries inside tests asserting on companion telemetry must be scoped via `within(chamber)` to avoid ambiguity when the file input displays the active filename simultaneously.
- Verification Multi-Pass Inspection Chamber & Telemetry Architecture: In `VerifyDocumentPage.tsx`, the `.verification-chamber` provides an analytical, forensic companion alongside the verification form, distinct from the constructive signing vault in `IssueDocumentPage.tsx`. It synchronizes across 5 stages: intake (01) -> optical_scan (02, laser optical scanning sweep) -> signal_extraction (03, observed wavelet DWT sub-bands LL/LH/HL/HH) -> signal_comparison (04, dual expected vs observed signal tracks with dynamic bar levels and region reticles) -> resolution_handoff (05, evidence resolution wave). In the upload dropzone, `.scan-laser-wrap` coordinates primary and secondary laser beams with a phase offset (`.scan-laser-beam-primary`, `.scan-laser-beam-secondary`) instead of an isolated loop.
- Verification Telemetry DOM Scoping Invariant: When asserting on selected file names in tests (e.g. `suspect.pdf`), both the dropzone file picker (`.file-name`) and the companion inspection chamber telemetry (`.chamber-telemetry-value`) render the active file name. Test queries must be scoped to the chamber container (e.g. `chamber.querySelector(".chamber-telemetry-value")` or `within(chamber).getByText(...)`) to avoid DOM cardinality collisions in Testing Library.
- Spatial Job Progression & Polling Telemetry Invariant: In `apps/web/src/pages/JobDetailPage.tsx`, the job lifecycle track is upgraded into a spatial progression pipeline (`.job-spatial-pipeline`) integrating an inspection chamber (`.job-chamber`) with `<CryptographicMotif stage={motifStage} size={120} />` and a 4-stage connected progression track (`created` -> `queued` -> `processing` -> `succeeded`/`failed`). The motif stage dynamically reflects the operational workflow: for issuance `processing` -> `decomposing`, for verification `processing` -> `verifying`, `succeeded` -> `sealed`, and terminal failures/cancellations -> `tampered`. Flow connectors (`.step-connector`) between nodes dynamically display passed progress (`.is-passed`) and an active traveling flow beam (`.pipeline-flow-beam`) during execution. In GSAP, scoping to `containerRef` with `dependencies: [job.data?.status]` automatically halts infinite flow beam, active node ring, and telemetry pulse tweens when the job reaches terminal resolution, preventing lingering animations and memory leaks during long-running polling.
- Authoritative Result Payoff & Discrepancy Isolation Architecture: In `VerificationDetailPage.tsx` and `IssuanceDetailPage.tsx`, the final verification/issuance outcome acts as the definitive payoff of the motion system without decorative celebration. For intact/completed documents (`data-status="intact"` / `"sealed"`), concentric boundary rings (`.seal-concentric-rings` with `.ring-outer`, `.ring-mid`, `.ring-inner`), `<CryptographicMotif stage="sealed" />`, and an authoritative Ed25519 stamp seal lock (`.stamp-seal-lock`) converge into a stable verified state accompanied by geometric and cryptographic match readouts. For tampered/anomalous documents (`data-status="tampered"`), the UI strictly avoids reusing success animations with a red color palette; instead, it initiates a distinct forensic discrepancy isolation sequence featuring fractured geometry (`.fractured-geometry` with jagged SVG `.fracture-trace` stroke animations), bracketed corner reticles (`.discrepancy-reticle` with `DELTA_A`/`DELTA_B` tags), an evidence anomaly beacon (`.evidence-anomaly-beacon` with pulsing `.beacon-ping`), `<CryptographicMotif stage="tampered" />`, and a dedicated suspicious regions telemetry HUD (`.tamper-telemetry`). To prevent DOM cardinality collisions in Testing Library (`getByText`), the payoff card's narrative headlines ("Chứng thư xác thực toàn vẹn độc lập", "Cách ly sai lệch & Đo từ xa bất thường") remain structurally distinct from the forensic conclusions in `EvidenceSummary`.
- Workflow Stage Continuity & GSAP Terminal Tweens Cleanup Invariant: In `MotionRoute.tsx`, workflow routes are assigned spatial ranks (Rank 1: `/issue`, `/verify`; Rank 2: `/jobs/:id`; Rank 3: `/issuances/:id`, `/verifications/:id`). Forward progression triggers horizontal translation (+12px), while backward navigation translates (-12px), and intra-rank navigation uses vertical translation (+6px). To prevent stacking context issues, overflow clipping, or fixed header misalignments after route transitions and seal constructions, all terminal tweens must explicitly specify `clearProps: "transform,opacity,visibility"`. In `VerificationDetailPage.tsx`, terminal forward payoff tweens for `.seal-authoritative-badge`, `.seal-readout-item`, and `.tamper-metric` must include `clearProps: "transform,opacity"` to ensure clean DOM unmounts and static accessibility.
- Vite Local Reverse Proxy & Django CSRF/Cookie Normalizer Invariant: When running local frontend verification (`npm run dev` or `vite preview`) proxying to an HTTPS Django backend (`splitbind.qivarn.id.vn`), direct POST requests trigger HTTP 403 `{"detail":"CSRF validation failed."}` because Django verifies that `Origin` and `Referer` headers match `CSRF_TRUSTED_ORIGINS`. In `vite.config.ts`, `server.proxy` and `preview.proxy` configure `proxyReq` event listeners to rewrite `origin` and `referer` to `https://splitbind.qivarn.id.vn`. Furthermore, the downstream `set-cookie` header on `proxyRes` must strip `Secure` and `Domain` attributes and set `SameSite=Lax` to allow local HTTP browser storage of session and CSRF cookies on `127.0.0.1:5173`.
- Legacy Ghost CSS and Phantom Margin Invariant: When refactoring from sidebar navigation or side rails (`.side-rail`) to a top header (`.app-header`), any lingering media queries that applied horizontal offsets (such as `@media (min-width: 60rem) { .app-content { margin-inline-start: 7rem; } }`) must be completely purged. Otherwise, `margin-inline-start` pushes 100%-width content 112px to the right, causing horizontal scroll overflow that pushes the left form column out of view when scrolled horizontally. Both `.app-content` and `.route-stage` must declare `max-width: 100%; overflow-x: clip;` as a hard defensive boundary.
- Chamber Z-Index Stacking & Card Occlusion Invariant: In cryptographic chamber viewports (`.chamber-viewport`) where an SVG motif (`CryptographicMotif`) shares the center with a document ghost card (`.chamber-document-ghost`), `.chamber-motif` must be layered below the card (`z-index: 1; opacity: 0.45; pointer-events: none;`) and the document card must have a higher stacking context (`z-index: 3;`) with frosted glass backdrop styling (`background: rgba(255, 255, 255, 0.94); backdrop-filter: blur(8px); box-shadow: var(--shadow-md);`). This guarantees that SVG circular center nodes (`.motif-core`) never render directly over card header text (e.g. "DOC Chờ tệp", "IMG 396 KiB").
- Responsive Breakpoint Alignment for Laptop & Edge Sidebar Invariant: On laptop viewports (1366px or 1280px display) when browser sidebars (such as Microsoft Edge vertical sidebar or Copilot taking ~320px) are active, effective viewport width is between 1024px and 1150px. Confining two-column workbench layouts (`.workbench-layout`) to breakpoints of `max-width: 64rem` (1024px) creates layout collisions on laptop screens with open sidebars. Expanding the single-column collapsing breakpoint to `max-width: 72rem` (1152px) ensures the workbench form and companion chamber stack cleanly without horizontal overflow.
- GSAP Route Transition Layout Drift Invariant: In full-width page wrappers (`MotionRoute.tsx`), applying horizontal transforms (`x: deltaX`) triggers browser horizontal scrollbar flickering and persistent scroll offset shifts in Chromium/Edge browsers. Route transitions must use vertical rising fades (`y: 6` to `0`) and instantly reset window scroll offset (`window.scrollTo({ left: 0, top: 0, behavior: "instant" })`) upon route change.
- Hallmark Plain-Language Translation Invariant: Technical jargon in cryptographic security interfaces must be translated into intuitive, plain-language Vietnamese:
  - Raw 2D-DWT mathematical sub-bands `LL Xấp xỉ`, `HL Ngang`, `LH Dọc`, `HH Chéo` -> `Cấu trúc`, `Nét ngang`, `Nét dọc`, `Vân bảo mật`.
  - Signal comparison `Kỳ vọng` / `Quan sát` -> `Bản gốc đối chiếu` / `Tệp thực tế kiểm tra`.
  - Intact payoff -> `Tài liệu chính gốc, không bị chỉnh sửa` with clear readouts for `Dấu vết thủy vân`, `Chữ ký số`, `Mã kiểm tra tệp`.
  - Tampered payoff -> `Tài liệu đã bị can thiệp hoặc giả mạo` with `Chi tiết điểm nghi vấn`.
  - Footer label -> `Thủy vân số chống giả mạo & Ký số bảo vệ toàn vẹn`.

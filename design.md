# SplitBind — Evidence desk

Hallmark · modern-minimal · designed-as-app · custom: precise, calm, technical, authoritative.

## Product contract

Issuance creates a recipient-specific PDF and signed record. Verification reports the server verdict and available evidence, not a legal conclusion. Integrity Release matches exact files; never imply DWT/DCT detection or hidden watermark protection is available from an upload stage. Null evidence is unknown, not a pass. Errors and inconclusive results are not tampering.

## System

Application workbench family: a task-focused document desk, not a marketing screenshot tour. Navigation: two real destinations, compact horizontal tabs (N1a justified by exactly two tasks). Footer: inline single line (Ft2). No enrichment inside application pages. A static split-line brand mark connects document and evidence without simulated telemetry.

Paper: warm near-white. Ink: deep blue-green. Accent: restrained forest green. Warning: dark amber. Error: dark red. Tokens in apps/web/tokens.css are the source of truth. Manrope 700 headings and Inter 400 body are retained deliberately for Vietnamese coverage and local delivery; monospace is only for identifiers. Body 16px, labels 14px, h1 28–40px. A 4px spacing scale; 1120px overall content, 680px primary form, 280px unboxed help. Controls 48px, 6px corners. No card-in-card, gradient, glow or root overflow clipping.

## Composition

Login: short product explanation and one form; form first on mobile.
Issue: document, recipient, action, then short delivery guidance.
Verify: document and action, then scope explanation. Distinct task heading and instructions.
Job: real status, explanation, four server lifecycle steps, next action, record metadata. Never invent percentage or time remaining.
Results: verdict first, actionable downloads/next steps, evidence disclosure, metadata last. Each verdict has its own semantic tone. Missing data stays explicit.

Integrity reports use a dedicated algorithm-aware presentation: SHA-256 lookup and issuance-record signature only, plus page count when supplied. Success requires an intact status, an exact match and a valid signature together. A missing source is not evidence that a known document was edited. No-match signature checks are not performed; other missing signature evidence stays unresolved. Research scores, vote counts and region maps do not belong in integrity reports. Show one scope explanation and actionable next steps, without duplicate shell warnings. Stack evidence labels above values at narrow mobile widths.

## Motion and accessibility

One 180ms route opacity transition; one 220ms state resolution via scoped useGSAP with revertOnUpdate. No repeat loops except an indeterminate processing indicator. No ScrollTrigger. Reduced motion immediately shows final state. Errors/focus are instant. Native file controls support keyboard and drop, visible labels, local file selection is distinct from server upload. Mobile navigation stays directly available; no hidden drawer for two destinations. Long values wrap at source.

## Validation

Fresh tests, typecheck, build, diff check plus real Chromium at 1920x1080, 1280x800, 768x1024, 375x667 and narrow-width smoke. API fixtures exercise real frontend but do not prove live server cryptography. Before/after screenshots and iterative inspection required.
